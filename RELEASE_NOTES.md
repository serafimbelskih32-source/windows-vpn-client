**The server changes without a reconnect, and “Fastest from the list” now weighs ping and speed together.**

- **Click another server while connected, and the connection moves to it.** Before, the click only remembered the choice and you had to disconnect and connect again. Now the running core is told to switch: it takes a moment, the network adapter is never taken down, so nothing can leave around the VPN while the server changes. Connections that were open on the old server are closed, and the applications reopen them through the new one. Going through the list with the arrow keys switches only once, to the last row.
- **When it cannot switch, nothing leaks.** A server that does not answer means no traffic at all, not a direct one: the program says so and waits for you to pick another. A switch the core refuses leaves the connection where it was. A server that appeared after you connected (the subscription refreshed) cannot be added to a running core: the program tells you to reconnect once and stays on the current server meanwhile.
- **“Fastest from the list” no longer goes by ping alone.** The lowest ping can sit on a 5 Mbit/s line while a server with a ping a little higher gives 150 Mbit/s. Ping is what messages, calls, games and opening pages feel; speed is what video and downloads feel. Both are turned into a score that saturates (past a point more speed or a lower ping helps less), and the connection goes to the best score only for a clear gain (25% better), so it does not hop between near-equal servers.
- **How it gets the numbers.** Right after connecting (and every half hour) the program measures the speed of the best few servers by ping, a few seconds each, tens of megabytes in all, around the tunnel, while the connection already works on the core's own pick. If the server it is on stops answering twice in a row, it moves to the next best within about half a minute, and to the core's own group if none is left. A server you pick by hand is never replaced.
- **Your choice, in the advanced settings.** “What matters more when choosing a server”: Balanced (default), Response time (calls, games, websites), Speed (video, downloads). “Weigh speed, not only response time” switches the speed runs off (then only the ping counts, as before; it also stays off when speed or ping is switched off in “Settings”).
- **The list and the test follow the same rule.** The order of the list is the order of advice, and the test says which server is the best choice, and when another has a lower ping, why it is not chosen (“… has a lower response time, but its speed is …”).

What is not covered, honestly: if the VPN core itself crashes, or you disconnect, the adapter goes with it and traffic is direct until the program reconnects (on Windows it does so by itself, within a few seconds). A firewall “kill switch” for that moment is not in this version.

**Сервер меняется без переподключения, а «Быстрейший из списка» теперь учитывает отклик и скорость вместе.**

- **Нажми на другой сервер при включённом VPN, и соединение перейдёт на него.** Раньше нажатие только запоминало выбор, и приходилось отключаться и подключаться заново. Теперь работающему ядру говорят переключиться: это занимает мгновение, сетевой адаптер ни на секунду не убирается, поэтому пока сервер меняется, ничего не может уйти мимо VPN. Соединения, которые были открыты на старом сервере, закрываются, и программы открывают их заново через новый. Если пролистывать список стрелками, переключение будет одно, на последнюю строку.
- **Если переключить нельзя, ничего не утекает.** Сервер, который не отвечает, значит никакого трафика, а не прямой выход: программа так и скажет и будет ждать, пока ты выберешь другой. Переключение, которое ядро отклонило, оставляет соединение где было. Сервер, появившийся после подключения (обновилась подписка), нельзя добавить в работающее ядро: программа попросит один раз переподключиться и пока остаётся на текущем.
- **«Быстрейший из списка» больше не смотрит на один пинг.** Самый низкий пинг может оказаться на канале в 5 Мбит/с, а у сервера с чуть большим пингом бывает 150 Мбит/с. Пинг это то, что чувствуют сообщения, звонки, игры и открытие страниц; скорость это то, что чувствуют видео и загрузки. Оба превращаются в оценку, которая насыщается (после какого-то предела больше скорости или меньше пинга помогает всё слабее), а соединение переходит на лучшую оценку только при заметном выигрыше (на 25%), чтобы не прыгать между почти равными серверами.
- **Откуда числа.** Сразу после подключения (и потом раз в полчаса) программа измеряет скорость у нескольких лучших по пингу серверов, по несколько секунд, всего десятки мегабайт, мимо туннеля, пока соединение уже работает на выборе самого ядра. Если сервер, на котором она сидит, дважды подряд не ответил, она примерно за полминуты уходит на следующий лучший, а если не осталось ни одного, на собственную группу ядра. Сервер, выбранный вручную, никогда не подменяется.
- **Что важнее, выбираешь ты, в расширенных настройках.** «Что важнее при выборе сервера»: Поровну (по умолчанию), Отклик (звонки, игры, сайты), Скорость (видео, загрузки). «Учитывать скорость, а не только отклик» отключает замеры скорости (тогда решает один пинг, как раньше; так же происходит, если в «Настройках» выключены скорость или пинг).
- **Список и тест подчиняются тому же правилу.** Порядок в списке это порядок совета, а тест говорит, какой сервер лучший выбор, и если у другого пинг ниже, объясняет, почему он не выбран («Отклик ниже у …, но скорость там …»).

Чего здесь нет, честно: если упало само ядро VPN или ты отключился, адаптер исчезает вместе с ним, и трафик идёт напрямую, пока программа не подключится снова (на Windows она делает это сама, за несколько секунд). «Рубильника» в брандмауэре на этот момент в этой версии нет.
